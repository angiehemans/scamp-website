### Design component variants as a set `shipped`

- A component's variant properties, such as a button's `variant` and `size`, live in the **Variants** section of the properties panel. The canvas draws every combination as a frame in a grid, and you edit any frame by clicking it
- A frame that combines two values writes a rule for just that combination, and **Make default** changes the component's own look. Scamp writes each value as a `data-` attribute rule, which runs with no JavaScript
- **Pick a variant for each instance.** An instance's section in the properties panel has a list for each axis, so one Button component gives you a primary and an outline button on the same page
- **Change a variant on hover, press, focus, or click.** A component's **Interactions** change its own variant while it's used: a button's hover look, a menu that opens on a click and closes on a click outside or Escape. Hover, press, and focus are CSS; clicks run through the Scamp framework. **Preview** on a component opens it alone in the Preview window to try them
- **Starter Button, Modal, and Menu components.** Add one from **Starters** in the Components list to reuse, restyle, or learn from. In a Scamp framework project, the Modal and Menu open and close by themselves, and fade in and out. [Components](/docs/components#add-a-variant)

### Variants everywhere `shipped`

- **A React import keeps each component's looks as variants.** Where copies of a component differ only in paint, such as the current item in a navigation menu, each look becomes a variant the page's instance picks
- **Checks find variant mistakes.** An instance set to a value its component lacks, and a rule for a value the component doesn't declare, are both listed
- **The Scamp Agent builds components with variants.** Ask it for an outline button or a small size, and it adds variant properties, values, and interactions to one component rather than copying the component per look. It asks before it removes a property or value. Agents connected over MCP get the same guidance in `agent.md`

### Changes `shipped`

- **Components are purple.** A component's set border, its icon in the **Layers** panel, and a selected instance use purple, so you can tell a component from a page element at a glance
- **A cleaner component editor.** The banner above the canvas is gone; the breadcrumb, such as `home › Card`, names where you came from, and you click its first part or press **Esc** to go back. **Routes** no longer shows while you edit a component
- **Variants and Interactions follow Figma's layout.** Each section adds with **+** in its header. An interaction is added from a panel with **Trigger** and **Action**, starts from the value you're editing, and is listed on one line

### Fixes `shipped`

- **An agent's edit no longer wipes your unsaved change.** Scamp now merges the two
- **Following a link to another page keeps your last edits.** Jumping through the link indicator saves the page you leave first, as the sidebar does
- **Restoring a snapshot is safe.** Restoring your oldest snapshot no longer deletes it without restoring, and a restore that fails partway puts the project back as it was
- **A failed save no longer leaves a page half-written.** Scamp writes a page's `.tsx` and CSS together, or neither
- **Undo can't bring a deleted page back into a new one.** A new page with a deleted page's name starts with its own history
- **Update scampjs works right after a release**, instead of failing with `ETARGET` while npm's cache was behind
- **Security.** On Linux, Scamp no longer stores your sign-in and API key when the system keyring offers only its fixed, publicly known key. MCP connection files are readable by your user only, an image download during an import is capped in size and time, the preview opens a new window only after a click, and an agent's heavy queries run one at a time
